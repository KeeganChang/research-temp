# 安全删除规则（safe-delete）

本文件定义 file-manager 的删除策略。SKILL.md 只引用本文件，不内联规则。

## 适用范围

- **工作区（`<workspace>`）内**：完全访问模式下可任意新建 / 编辑 / 删除（CRUD）。
- **工作区外个人目录**（Desktop / Downloads / Documents / Home 等）：仅只读扫描，删除须用户显式确认，走回收站。

## 核心原则

1. **可逆优先**：删除默认进回收站（`shutil.move` 到 `.trash/<日期>/`），不直连 `Remove-Item -Force` 或 `rm -rf` 物理删除。
2. **禁止吞错**：绝不使用 `-ErrorAction SilentlyContinue` 或 `2>/dev/null` 掩盖删除失败。删除命令必须暴露真实结果。
3. **删后验证**：删除后必须验证目标确实不存在（Read / 存在性检查），不能只凭 exit code 判断（沙箱环境 exit 0 不代表真实落盘）。
4. **危险命令隔离**：`rm -rf`、`Remove-Item -Recurse -Force`、通配符删（`*.tmp`）只在明确范围时使用，且先 dry-run 列出再执行。

## 工作区外个人目录（高危险）

- 只读扫描：只生成路径 / 大小 / 日期报告，不移动 / 改名 / 删除。
- 删除前必须：① 警告不可逆风险 ② 列出全部受影响路径 ③ 用户显式确认 ④ 走回收站（非物理删）。
- 每批最多 10 个文件，逐批验证。

## 回收站实现

- 路径：`.trash/<YYYY-MM-DD>/`
- 用 `shutil.move`（Python）或 `Move-Item`（PowerShell）移动，保留原目录结构。
- 物理清理由用户定期手动执行，或由带确认的一次性自动化完成。
- 工作区内删除若执行环境为临时沙箱（修改不落真实磁盘），应改用真实文件系统后再执行，并验证落盘。
