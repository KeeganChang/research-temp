## 二、M1 板块资金流：配方与坑

### 配方

查询措辞（命中「板块资金主力统计」）：

```
A股今日各行业板块主力资金净流入净流出排名 板块资金主力统计
```

### 已知坑

1. **只有日频（T+1），无周/月聚合接口。** 这是最关键的口径限制。
   - 「近一周」默认 = **最新交易日快照**，必须在交付物里明示。
   - 用户要严格 N 日累计 → **逐日拉取后求和**（同一查询改日期措辞，或按交易日循环），成本 = N 次查询。
2. **必须同时取流出侧。** 只报 Top10 流入会丢掉最重要的反向信号。
3. **概念层可作第二路证据。** 概念板块（军民融合 / 低空经济 / 央企）与行业层相互佐证，满足 M1「≥2 路独立证据」门禁。
4. 返回值可能混有「行业涨跌排行」而非「资金流排行」——**检查返回体是否含净流入/净流出字段**，没有就是命中错接口，换措辞重试。
5. **行业级资金流常常来自资讯正文，不是结构化接口（实测）**：`apiData.apiRecall[0]` 命中「统一资金流向」时返回的是**单个指数代码**（如 `01000000.PT`），且注明「本次调用未返回时间字段」、数值全为 0 —— 不是行业排名。真正的申万行业排名在 **`data.docData.docRecall[0].docList[].content`** 的资讯正文里（证券时报 / Wind）。
   → 解析优先级：`docList` 正文 > `apiRecall`；同一事件常有多篇同源稿（实测 3 篇），**取最长的一篇解析、用其余交叉验证**。
6. **正文提取必须按行业名定向匹配**：通用正则 `[\u4e00-\u9fa5]{2,6}遭主力资金净流出` 会抓到「**子遭**主力资金」这类子串污染（"电子"的后两字）。
   → 正确写法：遍历已知行业名单，逐个 `re.search(行业名 + r"[^，。]*?(?:获得逾?([\d.]+)亿元|净流出(?:逾|超)([\d.]+)亿元)")`。
7. **数值分「逾」与「超」两种，精度不同**：「获得**逾** 39 亿元」= 精确到 39 的下限；「也获得**超**亿元净流入」= 只知 >1 亿。后者必须标 `lower_bound: true`，**不可与前者同权排序**。

## 三、M2 板块月 K：配方与坑

### 配方（带 fallback）

措辞 A（先试）：

```
<行业>板块指数 <年>年 月K线 每月涨跌幅 月度收益率
```

措辞 B（A 未命中「统一行情查询 / 历史行情」时改用，实测更稳）：

```
<行业> 板块 历史行情 月K线 <年>
```

### 已知坑（实测）

1. **板块名识别不稳定。** 实测中「石油石化 / 食品饮料 / 有色金属」用措辞 A 未命中，改用措辞 B 后全部命中。
   → **解析阶段必须校验命中数**，未命中的行业换措辞 B 重拉，不要静默丢弃。
2. **接口会省略某些月份。** 实测 2026 年序列缺 1 月月末。
   → 后果：2026-02 那一列实际是「上年末 → 2 月底」的**跨 2 月累计**，若当单月涨幅解读即错。
   → **处理**：标注缺失，或统一登记为"该列为跨月累计"。
3. **返回的最后一个点是最新交易日**（如 2026-10-29），不是月末。
   → 最后一个"月度点"实为**当月截至最新日**的涨跌幅，须标注（否则与真实月度环比不可比）。

## 四、批量采集与解析范式

### 采集

- 多行业**并行拉取**，每个行业结果**单独存 JSON**（不要打到 stdout 刷屏）。
- 落盘目录：`<workspace>/output/<主题>/`。
- 每个文件保留原始返回，便于回溯与二次解析。

### 解析

写一个统一的解析脚本，做三件事：

1. 从各 JSON 中提取「日期 → 收盘价」序列（**先探测返回体结构**，不同接口字段名不同）。
2. 算月度环比、归一化（基准日 = 100）、YTD。
3. **一致性校验**：打印每个行业的点数、首值、末值，逐个确认；点数异常（<10）即标为未命中并重拉。

### 校验输出示例

```
行业        点数   基准值(2025-12-31)   最新值(2026-10-29)
银行        10    xxxx                xxxx
...
```

**未全部命中不得进入 M3。**

## 五、结论文本必须脚本生成（血泪教训）

- 实测中手写叙述曾把「交通运输 -10.7%、食品饮料 -14.0%」写成"红利正收益"，与自动计算的 YTD 直接矛盾。
- **硬规矩**：交付物中的**所有数值与胜负判断由数据脚本输出**，叙述文字引用脚本结果；若手写，必须逐条与脚本输出核对。
- 建议做法：脚本同时输出一张排序表，叙述按该表写；改数据后重跑脚本即自动同步。

## 六、可视化与渲染约定

- **A股色规：涨红跌绿**；货币用 **¥**。IDE 为 light 主题时，图表底色取浅色、文字取深色。
- 三张标准图：① 行业 × 月份 热力图 ② 归一化走势折线 ③ YTD 收益条形。
- 交付物先落 `<workspace>/output/`，用户确认后再移 `archive/raw/<type>/`（带 frontmatter，经 `validate_frontmatter` 校验）。
- **可视化渲染不是本 method 的职责**，method 只定义"要出哪几张图、每张图的口径"。

## 七、状态机回写清单

跑完一轮后，回写 `research-state.yaml`：

- `claims`：四象限归类结论、主推行业判断（带 `confidence` + `status`）
- `monitors`：
  - 主推行业月度环比（跌破阈值告警）
  - 主推行业主力净流入方向（反转告警）
  - 象限迁移（**双高 → 脉冲** 为最强减仓信号）
- `datasets`：本次采集的板块月 K / 资金流原始 JSON 索引（**防重复抓数**）
- `queue`：未命中行业的重拉任务（带 `depends_on`）
