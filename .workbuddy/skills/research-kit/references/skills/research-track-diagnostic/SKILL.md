# research-track-diagnostic — 诊断归因（Diagnostic）

> 方法级 Track 之一。推理方向 = **逆向·果→因**。用于「现状偏离目标 / 出问题了，为什么」。

## 适用
目标：定位现状偏离目标的根因，给出可执行的修复路径。典型：经营健康度诊断、漏斗转化诊断、渠道归因、方差分析。

## 通用四段（每段带门禁）

### G1 现状偏差 / 目标落差
- 问题：实际 vs 目标 / 预期差在哪？量化落差。
- 门禁：落差可量化、有基线，方可拆解。

### G2 拆指标定位异常环节
- 问题：哪一层 / 哪一环节偏离最严重？
- 门禁：锁定 1–3 个异常环节（漏斗/单元经济/健康度），方可溯因。

### G3 根因假设
- 方法：5-Why / 鱼骨图 / 方差分解，提出可证伪根因假设。
- 门禁：每条假设可验证（有对照或消融设计），方可验证。

### G4 验证根因 + 修复
- 问题：哪个假设被证据支持？对应修复动作性价比如何？
- 门禁：给出根因诊断 + 修复优先级（影响×成本），方可成稿。

## 反方（G4 强制 ≥5 条）
含「相关性≠因果」「幸存者偏差」「指标口径变化导致的伪落差」「外生冲击误判为内部问题」「修复副作用」。

## 交付形态
根因诊断书（含证据链）+ 修复优先级矩阵 + 监控指标（防复发）。落 `claims`，回写 `monitors`。

## 接入
- 具体框架：belongs_to_track: diagnostic 的 method skill（漏斗诊断 / 健康度 / 归因）。
- 已有 method：`method-ecommerce-ops`（电商 / 直播电商经营诊断：健康基线对齐 → 渠道 / 流量 / 漏斗 / 货品主播四维拆解 → 根因假设 + 修复优先级矩阵；按语境按需加载，无契合回退本骨架）。
- 注意：归因结论须标注「可证伪条件」，防止把相关性当因果。
