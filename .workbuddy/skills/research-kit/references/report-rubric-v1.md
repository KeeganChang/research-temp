# 报告质量评分卡 v1（Report Quality Rubric）

> **定位**：证据链精简方案 v1.1 的待立项项（原"报告质量 rubric 缺失"标注为阻断性）。
> **两阶段时机**（采纳用户 2026-11-02 反馈）：规则**前置为自检清单**（执行前可见、执行中对照），评分**后置**（交付后五维打分）。
> **参照**：Anthropic 多智能体研究系统的 LLM-as-judge 五维 rubric（事实准确性 / 引用准确性 / 完整性 / 来源质量 / 工具效率）。
> `derived_from`: 证据链精简方案 v1.1 §8 Q3 + Anthropic《How we built our multi-agent research system》(2025-06-13)。

---

## 0. 适用分层

| 输出类型 | 用哪部分 | 是否评分 |
|---|---|---|
| 轻量（一次性 / 答案唯一） | 仅 §1 前置清单 | 不单独评分 |
| 重型（对外 / 入决策 / 多人协作） | §1 前置清单 + §2 后置五维 | 评分，打回制 |

> 原则：内嵌引用成本近零，任何任务都该做；评分只在价值足够高时才划算（对应 Anthropic 的 15× token 成本约束）。

## 1. 前置自检清单（执行前 / 中门禁）

每条 deliverable 收尾前逐条过；任一未过不得交付。本清单**焊进 method skill 当门禁**（轻量模式前/中合并，不单列评分 pass）。

- [ ] 每个关键数字有**内联引用**（来源文件 + 短引文 + 抓取时间），无 `[UNSOURCED]`。
- [ ] 顶部有**口径块**（单位 / 基准日 / 缺月处理 / 代理指标定义 / known caveat）。
- [ ] **反方 ≥5 条**，且至少 **1 条为时间维度**。
- [ ] 原始返回**独立落盘**（服务复算），不进报告正文。
- [ ] 结论由脚本生成 / 校验，无手写数字与计算值矛盾。
- [ ] 若多源：标注每个来源**发布方**，`≥2 路真正独立源`（不同发布方 / 不同数据源）；同源转载（同一家媒体 + 同一上游如 Wind）不计数。
- [ ] 判断类结论标 `kind: judgment`，并记下**被否决的备选**阈值 / 结论（防阈值切换导致的归类漂移）。
- [ ] **同比 / 环比项双年（期）并列**写出（今年值 + 去年值 + 变化），不只写变化量。
- [ ] **比率类指标已拆分子分母**（覆盖率 / 拨贷比 / ROE / 中收占比）；未把「分母扩张」误读为「主动释放」。
- [ ] **关键数字已回一手**，聚合源仅作交叉校验；存在未裁决的多源冲突即不得交付。

> 后三条来自 2026-11-04 银行回源暴露的真实错误，动作定义与实例见 `references/data-integrity.md`（E1–E5 / A1–A5）。

## 2. 后置五维评分（重型输出）

每维打分 **0 / 1 / 2**（0=缺失，1=部分，2=充分），附一句判定与改进点。

| 维度 | 问的问题 | 2 分标准 | 常见失分 |
|---|---|---|---|
| **事实准确性** | 数字 / 事实对吗？ | 关键数字均可由原始返回复算，无矛盾 | 手写数字 ≠ 计算值；单位 / 基准日混用；同比基数取错年份；比率未拆分子分母 |
| **引用准确性** | 引用的来源真支持该结论吗？ | 每条 claim 的引用确实存在且**语义匹配** | 真来源但不支持结论（语义错配）—— 最难自动判 |
| **完整性** | 反方 / 边界 / 失效都讲了吗？ | 反方 ≥5（含时间维度），失效阈值明示，流出侧不省 | 单边叙事；漏掉流出侧同量级信号 |
| **来源质量** | 来源够独立 / 一手吗？ | ≥2 路真正独立源，优先一手 | 3 篇同源转载当 2 源（P06 实际栽过） |
| **工具效率** | 投入与任务复杂度匹配吗？ | 轻量任务没开重流程 / 多 agent / 台账 | 一次性问题跑全量门禁 + manifest |

**通过线**：总分 ≥ 8/10 且**任一维不为 0** → 通过；任一维 = 0 → 打回补对应项。

---

## 3. 与状态机的关系

rubric **不依赖状态机**。状态机降级为可选复用层（v1.1 §3.4）后，rubric 是**准确性保障的主干**——
它替代了原先"把状态机当成准确性层"的错位认知。两者分工：

- **rubric（准确性）**：保障本次交付对不对、源不源、全不全。
- **状态机（复用层）**：仅在月频重跑 / 跨会话续做 / 多人协作时，承担"上次到过哪、阈值怎么变"的记忆。
