# 研究粒度规则

> 回答三个问题：**这件事该拆成独立 task 还是留在 task 内循环**、**哪些维度允许扇出**、**查到什么时候算够**。
> 本文只管「怎么切」；信息存哪、报告怎么写由 `report-rubric-v1.md` + `delivery-standard.md` 管。

---

## 0. 一句话

**切分维度是「生命周期」，不是「层级」。**

银行调研的层级（行业→子行业→单家银行→科目）是数据树的深度，不是状态机的状态维度。把层级塞进状态机会让状态数变成乘积（20 家 × 3 层 × 5 阶段 = 300 个状态），不可维护；全部拆成 task 则会切断跨层因果链（宏观利率→同业价格战→资产结构），任何一段都无法独立推理。

---

## 1. 四条切分判据（G1 立项时逐条问）

同一组判据既决定「要不要拆」，也决定「拆到哪停」。

| # | 判据 | 满足 → 拆成独立 task | 银行对照 |
|---|---|---|---|
| G1-1 | 终止条件不同 | 各自有独立的「做完了」标准 | 每家银行覆盖度门槛不同 ✅ |
| G1-2 | 失败需隔离 | 一家失败不应拖垮全部 | 某家数据缺失不耽误其余 ✅ |
| G1-3 | 有独立人工闸门 | 需停下来等人拍板 | 某家纳入/剔除需确认 ✅ |
| G1-4 | 产物可独立交付 | 各自一份可直接交付的结论 | 一份单行研报 ✅ |
| — | **反判据** | 只是同一结论的中间材料 | 行业→子行业→科目 ❌ 四条全不满足 |

**判据全部不满足时，留在 task 内用循环遍历对象，不要拆。**

---

## 2. 扇出轴白名单

扇出 = 生成并列 task。**只允许沿「能产出独立结论」的轴扇出**：

| 允许 | 说明 | 例 |
|---|---|---|
| 对象 | 子系统 / 子标的 / 子区域 | 6 家银行、5 个光伏企业 |
| 子行业 | 分类体系下的并列分组 | 申万二级：国有行 / 股份行 / 城商行 / 农商行 |
| 情景 | 情景推演的互斥分支 | 乐观 / 中性 / 悲观 |

| 禁止 | 为什么 |
|---|---|
| 层级 / 深度 | 会让状态数变乘积，见 §0 |
| 章节 / 段落 | 那是**写作结构**，不是调研结构；按章节扇出会把同一对象的事实切散 |
| 指标 | 指标是 task 内部的数据字段，不配独立 task |

---

## 3. 两级状态机

```
父状态机（task 生命周期）：立项 → 扇出 → 执行中 → 归集 → 结案
        │ fanout(objects[])
        ▼
子状态机（单对象下钻）：定位 → 采集 → 交叉验证 → 饱和 → 交付
```

父子之间只有两条契约：**分发**（产生 N 个子实例）与 **结案**（汇总饱和状态）。

---

## 4. 饱和判据（替代「查够 N 个来源」）

```
饱和 = 本轮边际新增有效事实 < 1  且  缺口清单为空
```

- **按边际收益判，不按计数判**。`来源 ≥5` 是计数门槛，5 篇同源转载即可达标而信息未增加。
- 缺口清单显式列出「该对象还缺哪些 question」，为空才允许退出。
- **必须有硬上界**：设最大轮次（建议 3），到顶强制收敛并在交付物标注「未饱和，剩余缺口见 X」。禁止无限重试，也禁止「放宽时间范围凑来源数」——那是降标准而非补信息。

---

## 5. Join 策略

| 策略 | 用在哪 |
|---|---|
| **best-effort（默认）** | 同级对象归集。部分子 task 失败仍结案，失败项在结论里显式标注 |
| quorum | 需要「多数一致」才敢下判断的横截面对比 |
| all | 仅当缺任一项则整体结论失效（慎用，易被单点拖死） |

**禁止 all-or-nothing**：一个对象的失败不应让整份研究归零。

---

## 6. 深度分级（按 scope 分配预算）

| scope | 用在哪 | 预算 |
|---|---|---|
| `shallow` | 上下游 / 论据型对象 | 1–2 轮，只回答定位、议价来源、传导方向 |
| `deep` | 结论型对象（独立交付的标的） | 至饱和（§4） |

上下游对象**不展开财务、不估值**。深度预算不分开，必然全员深挖然后撞轮次上限。

---

## 7. 状态字段禁令

**`status` 里绝不出现 `L2_researching` 这类层级值。** 层级放 `level` / `depth_budget` 字段——它是数据，不是状态。一旦混进 status，状态机退化成有限自动机的乘积。

`parent_id` 用自引用：调研中发现新对象（如「该行并表了某村镇银行」），直接 spawn 子 task，状态机一行不用改。

## 8. 行业 → 扇出轴的映射（申万口径）

### 8.1 分类表给的是层级，不是上下游

申万 2021 版把银行放在一级行业 `801780`，二级五个：国有大型银行Ⅱ `801782` / 股份制银行Ⅱ `801783` / 城商行Ⅱ `801784` / 农商行Ⅱ `801785` / 其他银行Ⅱ `801786`。

**这张表是子行业扇出轴。** 申万不发布官方「上下游」映射表——正确做法是**以一级行业全集（31 个）为查找范围，再用资产负债表逐项对应**，而不是读现成的上下游字段。

### 8.2 上游与下游的扇出单位不同

| | 是否可比公司群 | 扇出单位 | 银行例 |
|---|---|---|---|
| 上游 | 是 | **公司** | 银行 IT：计算机→IT服务Ⅱ（宇信科技/长亮科技/神州信息）、软件开发（恒生电子）、计算机设备（广电运通） |
| 下游 | 否 | **行业** | 房地产 / 建筑装饰 / 机械设备 / 商贸零售 / 电子——是融资行业，不是公司 |

### 8.3 两条映射修正

- **下游 top 不按市值排，按敞口权重排**。银行下游要按贷款投向占比：市值排名会把电子排到房地产前面，而房地产在资产负债表上的权重是电子的数倍。
- **上下游的「论据三问」按行业改写**。银行对下游没有供应链议价关系，只有**敞口权重 / 资产质量 / 定价能力**三件事。

### 8.4 不是所有行业都有产业链

银行、保险等金融行业没有上下游产业链，硬套「环节分层 + 兑现度矩阵」会变形。替代骨架：**资产负债表三段式（负债端—资产端—成本资本）+ 业务条线分层**，兑现度线只保留在「中收能否接住息差缺口」一处（T1.2 已实证）。

---

## 9. 动态提升

上下游行业里发现卡脖子环节时，运行期把它从「论据」提升为独立 task，不重启流程——这是 `parent_id` 自引用的兑现点。提升条件：该环节对主体结论有**方向性影响**，且当前 task 内已无预算深挖。

---

## 10. 反模式

| 反模式 | 症状 | 后果 |
|---|---|---|
| 按层级切 task | `status` 出现层级值 | 状态数爆炸 |
| 按章节扇出 | 同一对象的事实分散在多个 task | 上下文碎，归集时靠检索而非推理 |
| 全量深挖 | 上下游也做财务建模 | 撞 maxTurns，跑不完 |
| 计数式终止 | 「≥5 个来源」即停 | 5 篇同源转载达标但未饱和 |
| all-or-nothing join | 一个子 task 失败全案作废 | 单点拖死整体 |
| 把 task 树建成叶子平铺 | 行业级结论无归属地 | 「利润正在往上游转移」不属于任何一家公司，无处可写 |

---

## 11. 信息层：不建额外文件

数据的唯一归属地是**报告本身**：汇总表 + 脚注（来源 / 日期 / 是否审计），同指标多来源时在正文点名差异，口径写在开头。

不建 unit 文件、不建指标表、不建段落关联注释、不建置信度快照。判据只有一条：**同一份数据出现第二种存储格式，就是把它换个格式再存一遍**——几份副本必然趋于不一致，而判断「哪份对」的成本高于它省下的核对时间。

例外：跨产物复用、追责追溯、单份报告装不下，三条**同时**成立才启用独立事实层，且必须先证明报告本身确实承载不了。
