# research-industry — 行业深度调研子类

> `research` 大类下的**行业**子类，是 **Track A 景气链 Top-Down 的第二段**（macro → industry → company）。
> 模板：`archive/raw/行业/20260919_行业_半导体AI算力链深度_v1.md` 与同项目《半导体细分赛道三维打分》（均属项目 **P01 · 2026-09-19 行业热点观察**）。
> 分工：**macro 自上而下回答"钱在哪"；industry 自中而下回答"钱投的这条链谁真赚到钱、赚的是周期还是成长、什么时候会反噬"**；再交 `research-company` 落到单个标的。

## 何时用
- 宏观资金面已锁定某个热门行业，需要下钻到产业链做深度判断。
- 需要判断某行业的**业绩兑现度**（真兑现 / 伪兑现 / 周期弹性），而非只看涨幅。
- 需要一份可交给多智能体团队下游（公司研究 / 组合配置）的行业底稿。

## 铁律
1. **需求必须被财报或订单证实**，不允许只用"行业景气""政策利好"下结论——需求侧拿不出客户资本开支、收入增速、出货量中的任一项，就标 `confidence: low`。
2. **必须区分"周期"与"成长"**。涨幅与利润增速同源时，要回答：这是可持续的结构性需求，还是一轮价格周期？（存储/面板/航运类尤其重要）
3. **必须做环节分层**：行业内部从来不是齐步走，必须给出"哪一层已兑现 / 哪一层还在讲故事 / 哪一层是卡脖子"。
4. **必须给反方论点**，且至少一条是**时间维度的**（本轮逻辑会在什么时候、因为什么失效）。这是本报告最高价值的部分。
5. **估值表必须声明口径**（第三方测算 / 一致预期 / 公司指引），混用即废。
6. **A股色规：▲红=涨、▼绿=跌，货币 ¥**；不硬编码路径与私密信息（见 `AGENTS.md` 铁律）。

## 输入契约
| 项 | 说明 |
|----|------|
| 目标行业 | 如"AI 算力链""铝加工""动力电池" |
| 上游结论指针 | 来自哪份宏观/先前笔记（填 `reason` 与 claims `evidence`）|
| 数据窗口 | 通常取最近一个完整报告期（半年报/年报），显式声明 |
| 可选聚焦 | 指定要深挖的环节（默认全链路）|

## 方法论：六段式行业拆解（核心）

| 段 | 回答什么 | 必须拿到的证据 |
|----|---------|--------------|
| ① 需求侧 | 需求是真的吗？ | 下游客户**资本开支**、下游**收入增速**、出货/用量数据 |
| ② 供给侧 | 紧张到什么程度？ | **量**（产能/产量/出货）、**价**（涨价幅度/ASP）、**产能利用率/新建产能** |
| ③ Why now | 为什么是现在？ | 找 **2–3 条同时发生**的驱动，缺一不可；写成可证伪的组合 |
| ④ 产业链分层 | 内部谁强谁弱？ | 按**国产化率 / 技术代差 / 附加值**做三级梯队；指出"水位差" |
| ⑤ 环节玩家地图 | 每环节谁在赚钱？ | 逐环节 **H1 营收 / 同比 / 归母 / 同比** 表；标出**真正盈利的家数** |
| ⑥ Valuation & Ideas | 贵不贵、先跟谁？ | comps spread（含口径声明）+ idea shortlist（thesis + 主要风险）|

**贯穿全篇的一根线**：**兑现度**。每个环节都要回答"兑现 / 半兑现 / 未兑现"，最后汇总成一张《兑现度矩阵》——这是本报告区别于普通行业综述的关键产出。

## 输出契约

落盘路径：`archive/raw/行业/<日期>_行业_<主题>_v<版本>.md`
结构化明细：同目录同名 `.csv`（frontmatter 用 `data_file` 指向）。

**frontmatter（必填）**
```yaml
source: "<多源，含年度报告 / 披露平台 / 第三方研究机构>"
url: "<代表来源 URL，须 http(s) 开头>"
fetched_at: YYYY-MM-DD
type: 行业
structure: unstructured
confidence: high|medium|low
tags: [半导体, AI算力, ...]   # 经 config/tags.yaml 别名归一
keywords: [HBM, CoWoS, ...]
reason: "由宏观结论 C-XXXXXXXX-XX 推导——<一句话承接关系>"
data_file: <同名 .csv>
project: P01                # 所属调研项目（新建/确认：script/load_context.py --list）
claims_added:               # 可选，回写 research-state 的结论编号
  - C-20260919-06
```

**正文结构（模板，章节号固定）**
0. 一句话结论（含"兑现是分层的"这类核心判断）
1. 行业概览：需求侧（财报证实）/ 供给侧（量、价、产能）/ **Why now（三条同时发生）**
2. 产业链拆解与国产化水位（**三级梯队表**）
3. 竞争格局：按环节的玩家地图（逐环节财务表 + ⚠️ B 面提示）
4. 可比公司估值 comps spread（**含口径声明** + Outlier 标记 + 波动性表）
5. 研究优先级名单 idea shortlist（一句话 thesis + 主要风险；含"暂不列入"及理由）
6. **反方论点（强制，≥5 条，其中 ≥1 条必须是时间维度的失效点）**
7. 待验证（落入**本项目** `research/<PID>/research-state.yaml` 的 `queue`）
8. 证据与出处（分层列：披露 / 第三方 / 媒体 / 测算口径 / 行情）

## 执行流程
1. **先跑 `script/load_context.py --project <PID>`** 加载该项目状态机，确认上游结论、已有数据集（避免重复抓数）
2. 按六段式检索：**需求 → 供给 → why now → 分层 → 玩家财务 → 估值**
3. 逐环节打兑现度；识别**最需要警惕的组合**（如"估值最高 + 增速斜率最平"）
4. 写§6 反方论点，逐项过清单（见下）
5. 落 `output/` 暂存 → 用户确认 → 移 `archive/raw/行业/`
6. 跑 `script/validate_frontmatter.py` 校验
7. **回写本项目的 `research/<PID>/research-state.yaml`**：新增 claims（带 evidence/data 指针）、更新 monitors 观测值、queue 补 Q 条目（跨项目可复用的方法论另提升到 `research/_shared/`）
8. 交 **wiki-skill** 抽实体建双链 → `archive/wiki/行业/` + 更新 `MOC.md`

## 反方论点清单（写 §6 时逐项过）
- **时间维度的失效点**（最重要）：驱动因素何时减速？增速什么时候从三位数掉到两位数？有没有权威的**下一年**预测？
- **客户的钱够不够**：下游是"想投"还是"投得起"？看下游**自由现金流**是否已净流出（意愿与能力的背离）
- **估值分位**：PE/PB 历史分位是否 >90%？与历史抱团终局（2021 白酒 / 2022 新能源）的分位对比
- **筹码与波动**：看**区间振幅**而非只看 YTD——振幅巨大说明是筹码博弈不是稳步上行；有无单日踩踏先例
- **业内分歧**：有没有知名机构/基金经理公开表达相反观点？引原文
- **周期回摆**：若含周期属性，本轮景气已走了几个季度？历史完整景气一般多长？机构预测何时见顶
- **政策与地缘**：关税/管制范围是否可能扩大到终端品？二阶三阶环节（设备/材料）的薄弱带在哪
- **Outlier**：财务表中是否存在"高估值 + 低斜率""高利润 + 负现金流""业绩爆发 + 高管减持"的组合
