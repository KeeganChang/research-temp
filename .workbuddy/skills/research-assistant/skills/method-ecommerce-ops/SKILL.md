# method-ecommerce-ops — 电商经营诊断（diagnostic 的电商域实现）

> 本技能是 `research-track-diagnostic`（诊断归因**通用骨架**）在**电商 / 直播电商经营**语境的固化打法。
>
> **与骨架的分工（不重复）**：
> - 骨架 = 业务中立的推理过程：怎么量化落差、怎么拆指标、怎么提可证伪根因、怎么验证（`怎么归因`）。
> - 本技能 = 电商域的具体答法与口径：拆哪些维度、看哪些指标、什么算异常、what 算根因（`用什么算`）。
>
> 骨架里没有、也不该有「GMV / GPM / 千川 / 自然流量占比 / 货品组合」这类术语——它们属于本层。

## 启用方式

- 当前 `enabled: false`：**不参与** research-core 自动路由。
- 理由：diagnostic 亦用于 SaaS 漏斗、线下门店等非电商场景，默认启用会把非电商任务错误路由到电商口径。
- 启用：将 frontmatter 的 `enabled` 改为 `true`，本技能即作为 diagnostic 的电商经营诊断打法参与调度。

## 与骨架的映射

| 骨架阶段（通用） | 本技能实现（电商域） | 对应分析模块 |
|---|---|---|
| DG1 现状偏差 / 目标落差 | 定义经营健康基线 + 盘点渠道总盘（实际 vs 基线） | M1 |
| DG2 拆指标定位异常环节 | 四维拆解锁异常：渠道 / 流量 / 漏斗 / 货品主播 | M2 – M5 |
| DG3 根因假设 | 对异常环节提可证伪根因（5-Why / 鱼骨 / 方差分解） | R1 |
| DG4 验证根因 + 修复 | 验证 + 根因诊断书 + 修复优先级矩阵 + monitors | R2 |

## 分析任务清单（五段采集 M1–M5 + 两段归因 R1–R2）

> 这是本技能的核心：把「电商经营分析」拆成交接得起、门禁卡得住的七块。

### M1 定位与口径基线（对应 DG1）

- **输入**：业务覆盖的渠道清单、分析周期、经营目标与行业基线。
- **动作**：
  - 盘点渠道及其流量逻辑（抖音=内容推荐 / 淘宝=搜索+推荐 / 视频号=社交私域 / 快手=老铁信任），并按「人货场」标注差异。
  - 登记健康基线（电商/直播通用档）：人均停留 >60s、互动率 >5%、GPM >¥800、自然流量占比 >50%（成熟期）、付费 ROI >2.5、产品点击率 >10%、支付转化率 >3%。
  - 统一口径（见「关键口径」，凡跨平台对比必须先折算）。
- **输出**：渠道清单 + 基线表 + 口径登记表。
- **门禁**：落差可量化、有基线对照，方可拆解。

### M2 渠道经营对比（对应 DG2 · 第 1 维）

- **动作**：各渠道同台对比 —— GMV / 占比 / 观看人次 / 停留 / 互动率 / 支付转化率 / 客单价 / GPM / 自然流量占比 / 付费 ROI。
- **呈现**：核心指标总表 + 归一化雷达（多指标同台）。
- **输出**：指标总表 + 渠道分级（如「规模王 / 效率王 / 高客单 / 待起量」）。
- **门禁**：锁定 **1–3 个异常渠道**（含 GMV、效率双低的），方可继续。

### M3 流量结构拆解（对应 DG2 · 第 2 维）

- **动作**：各渠道「自然 vs 付费」占比分解；算流量获取效率与付费依赖度；对照分红期节奏（冷启动 70/30 → 成长 50/50 → 成熟 30/70）。
- **输出**：流量结构图 + 付费依赖告警。
- **门禁**：明确指出哪些渠道触发「**自然占比低 + 付费 ROI 低**」双低（这是最典型的经营亚健康信号）。

### M4 转化漏斗漏点（对应 DG2 · 第 3 维）

- **动作**：六层漏斗 —— 曝光 → 进入直播间 → 停留>30s → 点击购物车 → 下单 → 支付；算各层转化率，定位最大落差层。
- **输出**：多渠道漏斗对比 + 漏点定位。
- **门禁**：锁定**单一最大漏点**层，方可溯因（多处同时漏 = 拆解得不够细，退回 DG2）。

### M5 货品与主播经营（对应 DG2 · 第 4 维 · 供给端）

- **动作**：
  - 货品组合：引流款 / 爆款 / 利润款 / 秒杀福利款的占比与节奏匹配。
  - 主播能力矩阵：话术执行 / 节奏把控 / 临场应变 / 镜头感，识别单点依赖风险。
- **输出**：货盘表 + 主播矩阵 + 供给端根因候选。

### R1 根因假设（对应 DG3）

- 对 M2–M5 锁定的异常，用 5-Why / 鱼骨图 / 方差分解提出**可证伪**根因假设。
- 每条假设须写明「验证所需证据」与「可证伪条件」。
- ⚠️ 归因结论必须标注可证伪条件，防止把相关性当因果（如 GMV 涨 ≠ 效率提升，可能是投放加大）。

### R2 验证与修复（对应 DG4）

- 验证假设 → **根因诊断书**（含证据链）+ **修复优先级矩阵**（影响 × 成本，输出 P0/P1/P2 行动清单）。
- 若多渠道并存，须给**跨渠道资源再分配建议**（把预算从低 ROI 渠道挪向高 ROI 渠道，而非单纯加总预算）。
- 交付：全部结论落 `research-state.yaml` 的 `claims`；异常指标（自然占比 / ROI / GPM / 漏点率）回写 `monitors` 带阈值。

## 关键口径（须在 G4 登记）

| 口径 | 定义 | 常见坑 |
|---|---|---|
| GMV | 支付口径 或 确认收货口径**必须统一**，退款单列 | 两口径混用会导致伪落差 |
| GPM | GMV ÷ 观看人次 × 1000 | 「观看人次」含重复观看，跨平台口径不一 |
| 支付转化率 | 支付人数 ÷ 观看 UV（**注明 UV 口径**） | 勿与「订单数 ÷ 观看人次」混用，两者差一个量级 |
| UV 价值 | GMV ÷ 观看 UV | 同上，须与转化率同口径 |
| 自然流量占比 | 自然渠道进入人次 ÷ 总进入人次 | 「关注/私域」是否计入自然须明确 |
| 付费 ROI | 广告带来 GMV ÷ 广告消耗 | 千川 / 引力魔方 / ADQ / 磁力金牛 归因窗口不同 |

> 跨平台对比前必须折算口径；口径未登记直接对比 = G4 门禁不通过。

## 反方论点（G4 强制 ≥5 条）

1. **相关性 ≠ 因果**：GMV 涨是投放加大还是效率提升？须做同期对照。
2. **幸存者偏差**：只看 Top 渠道 / Top 主播，忽略长尾（如 GMV 高度集中在 2 位主播却未识别）。
3. **口径变化致伪落差**：GMV 口径切换、平台字段调整会被误读为「经营恶化」。
4. **外生冲击误判为内部问题**：大促节点、平台算法调整、季节性因素。
5. **修复副作用**：砍投放可提 ROI 但砸 GMV 规模；冲自然占比需牺牲短期转化——修复动作自身也有代价。

## 交付物

- 分渠道根因诊断书（含证据链）+ 跨渠道资源再分配建议。
- 修复优先级矩阵（影响 × 成本）+ P0/P1/P2 行动清单。
- 结论落 `claims`；异常指标回写 `monitors`（带阈值告警），满足防复发要求。

## 边界

- 仅用于「**已有电商经营对象，找为什么偏离目标**」的诊断。
- 若是「进不进某电商平台 / 新市场」→ `entry`；「选哪个平台 / 渠道最优」→ `drill`；二者不可与本 Track 混跑（见 ROUTING.md §三 反模式：**diagnostic 变 drill** —— 把经营诊断跑成下钻选优，只给最优环节却不定位根因）。
- 本技能负责**分析方法与结论**；报告渲染 / 可视化产出不在本技能职责范围（交付走 `output/` 约定）。
